把多个大模型供应商，变成一个本地端点

TokenHUB 是运行在 Windows 桌面的本地 API 网关。它把 OpenCode Go、DeepSeek、CommandCode 与任意兼容服务合并到一个地址，按优先级路由、额度耗尽自动切换，并让 Claude Code 与 OpenAI 客户端共用同一套模型目录。

Why a local gateway

为什么需要一个本地网关？

不是再做一个聊天客户端，而是把“用哪个供应商”这件事，从每个 Agent 的配置里收回来。

额度总在关键时刻用完

多家订阅轮流耗尽，手动改 Key 和环境变量；切完还要重启客户端，正在跑的任务被迫中断。

每个客户端一套配置

Claude Code 要 Anthropic 地址，Cursor / Continue 要 OpenAI 地址；同一个模型在不同供应商还叫不同名字。

出问题只能猜

429、余额不足、Key 失效看起来都像“模型报错”，没有统一的失败原因、耗时和切换记录。

TokenHUB 把这些统一到一个本地地址：一个模型目录、一套优先级、一份请求历史。客户端不需要知道背后有几家供应商。

How it works

请求只经过一个本地地址

客户端以为自己在调用 OpenAI 或 Anthropic；TokenHUB 负责选供应商、换协议、处理失败。

所有监听只发生在 127.0.0.1；图中不包含任何云端控制面。

左右滑动可查看完整架构图

1

客户端指向本地

OpenAI 客户端使用 http://127.0.0.1:8787/v1，Anthropic 客户端使用根地址。未启用本地访问 Key 时，API Key 可填任意占位值。

2

TokenHUB 选择路径

按供应商优先级选择；把本地模型 ID 映射到上游真实 ID；根据能力表决定直连还是转换请求形状。

3

失败自动接力

额度、限流、5xx 会切到下一个可用供应商。流式请求一旦开始返回内容就不再切换，避免半截回答被重放。

Feature set

一个网关，覆盖日常使用的全部环节

从选供应商到看用量，四件事都在本地完成：路由、转译、额度、记录。

优先级路由

供应商列表顺序就是路由顺序。拖动即调整，禁用即跳过，不需要改任何客户端配置。

自动故障转移

额度耗尽、限流、5xx 与网络错误会切到下一个可用供应商；额度与限流按各自策略冷却。

双协议互转

OpenAI Chat Completions 与 Anthropic Messages 双向转换，流式与非流式都支持。

统一模型 ID

同一个模型在多家供应商的上游 ID 可以映射到一个本地 ID；原始 ID 仍可用 providerId/原始ID 强制访问。

额度探针

OpenCode Go 显示三窗口，DeepSeek 显示余额；没有额度接口的供应商按 429 / 402 进入冷却。

历史与诊断

记录模型、供应商、Token、耗时、首字节、错误分类与切换来源；不保存提示词和回复正文。

密钥保险箱

供应商 Key 与本地访问 Key 由 Windows DPAPI 加密保存，界面不回显，日志与历史不落 Key。

托盘常驻

关闭窗口继续服务；托盘图标绿 / 黄 / 红表示健康度，菜单可暂停路由、复制地址或退出。

01 · 概览

一眼看清服务、额度和每一次请求

概览页是日常入口：先看服务是否在跑，再看额度是否够用，最后从最近请求里定位问题。

今日用量

请求数、Token、失败数与成功率都来自本地历史，不需要连云端控制台。

额度卡

按路由优先级排列；窗口百分比、重置倒计时与账户余额都在同一屏。

暂停路由

一键让所有 /v1 请求返回 503，客户端不会在维护期间误发请求。

02 · 供应商

把供应商排成一条优先级队列

从上到下就是路由顺序。上面先试，失败或冷却时自动落到下一个。

预设即用

OpenCode Go、CommandCode Goat、DeepSeek 三个预设会自动填好 Base URL 与额度适配器。

Key 加密保存

只在新增或更换时输入；列表只显示“已保存”，编辑时留空表示沿用原 Key。

手动模型

服务不提供 /models 时，可以直接填写模型 ID，用逗号分隔。

  • 测试连接

    保存前先拉一次模型列表并探测额度，确认 Key 与地址是否可用。

  • 额度与冷却

    可设置低余额阈值、额度耗尽后的冷却小时数，以及流式请求是否注入 usage。

  • 冷却与恢复

    额度、限流、瞬态失败会进入冷却；概览卡的「恢复」按钮可手动清零。

  • 排序与删除

    拖动即保存优先级；删除供应商会同时移除它的模型与统一模型目标。

03 · 模型

一个模型名，多个供应商兜底

模型页合并所有启用供应商的目录。统一模型把同一个模型的上游 ID 收拢到一个本地 ID，Agent 只记一个名字。

合并目录

同名模型只出现一次；路由时按供应商优先级与当前可用性依次尝试。

统一模型

显式映射优先；被映射的原始 ID 从 /v1/models 隐藏，仍可用 providerId/原始ID 强制访问。

自动建议

按名称相似度生成候选，只建议不自动合并；确认后才创建统一模型。

模型页的「扫描」是诊断请求：对每个模型向 /messages 与 /chat/completions 各发一个 max_tokens=16 的请求，把结果写入供应商配置。扫描不写历史，也不计供应商故障；只有同一模型两个入口都返回 401（Key 无效）才提前停止。

04 · 设置

端口、访问保护与托盘行为

设置页决定服务怎么被访问、怎么随系统启动，以及历史与额度探针的节奏。

服务端口

1–65535。新端口先启动，失败时旧端口继续可用；端口被占用不会导致应用打不开。

本地访问 Key

启用后 /v1 必须携带 Bearer 或 x-api-key；Key 不回显，关闭开关立即停用鉴权。

启动与托盘

开机自启（仅安装版）、启动时最小化、关闭窗口到托盘；托盘图标颜色表示健康度。

日志与额度

历史保留 7 / 30 / 90 天或永久；额度刷新 10–3600 秒，默认 60 秒。

端口被占用时应用仍然会打开。到设置页换一个端口保存即可重试；配置、Key 与历史都不会受影响。

Quick start

五分钟接入

以默认端口 8787 为例。如果改过端口，请以设置页「连接信息」为准。

1

安装并启动

运行 Windows 安装包，启动后 TokenHUB 会监听 127.0.0.1:8787。关闭窗口默认最小化到托盘，服务继续运行。

2

添加供应商

进入「供应商」→「添加供应商」，选择预设或自定义，填 Base URL 与 API Key。建议先点「测试连接」，确认模型列表与额度都能读到再保存。

3

刷新模型

保存后会自动发现模型；也可以回到「模型」页点「刷新全部」。服务不提供 /models 时，在编辑供应商里手动填写模型 ID。

4

把客户端指向本地

OpenAI 与 Anthropic 客户端各用一套地址。未启用本地访问 Key 时，API Key 填任意非空占位值即可；启用后请换成你在设置页保存的 Key。

OpenAI SDK / 兼容客户端

# 环境变量
OPENAI_BASE_URL=http://127.0.0.1:8787/v1
OPENAI_API_KEY=sk-local-placeholder

Claude Code / Anthropic 客户端

# 环境变量
ANTHROPIC_BASE_URL=http://127.0.0.1:8787
ANTHROPIC_AUTH_TOKEN=sk-local-placeholder
ANTHROPIC_MODEL=claude-sonnet-4-5

有的客户端使用 ANTHROPIC_API_KEY；按客户端文档选择即可，TokenHUB 只校验你在设置页保存的本地 Key。

5

发一条请求验证

OpenAI Chat Completions

curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer sk-local-placeholder" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat",
       "messages":[{"role":"user","content":"你好"}]}'

Anthropic Messages

curl http://127.0.0.1:8787/v1/messages \
  -H "x-api-key: sk-local-placeholder" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-sonnet-4-5","max_tokens":256,
       "messages":[{"role":"user","content":"你好"}]}'
6

回概览确认

概览页的今日请求、额度和最近请求会随调用更新。展开一条记录，可以看到实际使用的供应商、首字节耗时与是否发生过切换。

Routing rules

失败时会发生什么

路由严格按供应商顺序，不做轮询。下面这些规则决定什么时候换、什么时候停、会不会冷却。

表格可左右滑动查看完整内容

情况TokenHUB 的行为供应商状态
首选供应商可用直接转发，返回上游响应正常
402 额度耗尽 / 429 被判为额度问题切到下一个可用供应商额度冷却 默认 5 小时，可配置
429 限流切到下一个可用供应商限流冷却 按 Retry-After，缺失时 60 秒
401 / 403 鉴权失败跳过该供应商，继续尝试其他候选鉴权失败 等待恢复或换 Key
5xx / 网络错误 / 超时先按需换协议入口，再切到下一个可用供应商瞬态冷却 10 秒起，连续失败 20 / 40 / 60 秒
404 模型不存在先尝试另一协议入口，再切下一个有该模型的供应商，并触发一次目录刷新不冷却 刷新有 60 秒限流
400 / 422 请求本身有误不切换供应商；首字节前可能先换协议入口重试一次不变
客户端主动断开立即停止，不切换不冷却
流式已出首字节后中断结束当前流，不切换供应商瞬态冷却 10 秒起，连续失败退避到 60 秒；客户端主动断开除外
全部候选都不可用（禁用、鉴权失败或冷却）返回 503；有冷却中的候选时附带 Retry-After（最短剩余秒数）等待冷却或修复 Key
候选都尝试后仍失败返回最后一次上游失败的状态与错误体按最后一次失败处理
流式请求只有首字节前允许切换。一旦开始返回内容，TokenHUB 不会把请求重放到另一个供应商——这能避免客户端收到两段互相矛盾的回复。全部候选都在冷却时，服务返回 503 并附带 Retry-After，客户端按剩余秒数等待即可。

Protocol

两个入口，两种上游

TokenHUB 优先使用与客户端一致的协议形状；能力表明确不支持时，才换到另一种形状。

表格可左右滑动查看完整内容

客户端入口首选上游何时换入口说明
POST /v1/chat/completions/chat/completions首字节前 400 / 404 / 405 / 422 / 5xx，且另一入口未判死OpenAI 请求可转成 Anthropic 形状，响应再转回 OpenAI
POST /v1/messages/messages同上Anthropic 请求可转成 OpenAI 形状，SSE 再转回 Anthropic
POST /v1/messages/count_tokens本地估算—不请求上游，Claude Code 的 token 计数可直接使用
GET /v1/models本地合并目录—带 anthropic-version 时返回 Anthropic 形状
GET /health本地—返回运行状态与是否暂停

CommandCode Goat

claude* 模型只走 /messages，其余模型只走 /chat/completions；预设会按模型名自动判断。

OpenCode Go

两个入口都可用；请求会优先保持客户端原本的协议形状。

DeepSeek / 自定义

默认按 Chat 处理；需要 Messages 入口时，先扫描确认或在能力表中显式标记。

换入口只发生在首字节前。401 / 402 / 429 不会换入口——两种形状共用同一把 Key，重试没有意义；流式开始输出后也不会再换。

Security & privacy

Key 和提示词，都不应该离开本机

TokenHUB 是本地进程，不是云端中转。它只在处理请求时把内容转发给你选择的供应商。

只监听回环地址

服务绑定 127.0.0.1，不接受局域网或公网连接，不需要开放防火墙端口。

DPAPI 加密保存

供应商 Key 与本地访问 Key 存在 secrets.bin，由 Windows 加密保护，不写明文配置。

界面与日志不回显

只显示“已保存 / 未配置”；历史与日志里不会出现 Key 内容。

可选的本地访问保护

开启后请求必须带 Bearer 或 x-api-key；关闭时本机程序可直接访问，适合单人开发机。

历史仅保留元数据

记录时间、模型、供应商、状态、Token、耗时与错误分类，不保存提示词和回复正文。

请求边界

请求体上限 20 MB；上游地址默认只允许 https，本机回环可用 http。

单实例与导航隔离

同一时间只运行一个实例；渲染层禁用 Node，外部链接与新窗口会被拦截。

没有遥测上报

不做用量分析或行为上报；只有你主动发起的请求会到达对应供应商。

迁移提醒：config.json 与历史可以复制；secrets.bin 与写入它的 Windows 用户 / 实例绑定，复制到其他数据目录会解密失败并被隔离。换机时建议重新录入 Key。

FAQ

常见问题

端口 8787 被占用了怎么办？

应用仍然会打开，但概览和设置页会提示服务未启动。到「设置」把端口改成另一个可用值并保存即可；旧配置、Key 和历史不受影响。新端口启动失败时，旧端口会继续服务。

Key 填错了会怎样？

上游返回 401 / 403 时，该供应商会被标记为鉴权失败并跳过。更新 Key 后会自动清除该状态；也可以在概览卡上点「恢复」手动清零。

模型列表是空的？

先点「刷新全部」。有些服务不提供 /models 接口，这时编辑供应商并手动填写模型 ID。请求一个本地目录里没有的模型也会触发一次目录刷新，但 60 秒内最多一次。

为什么有的供应商没有额度条？

只有 OpenCode Go（三窗口）与 DeepSeek（余额）提供额度接口。CommandCode 等没有公开额度接口的供应商会根据 429 / 402 错误码进入冷却，因此卡片上只显示状态与冷却倒计时。

额度多久刷新一次？

默认 60 秒，可在设置页调整为 10–3600 秒。DeepSeek 余额最多每 5 分钟探测一次，避免频繁请求。探测失败不会改变路由状态，连续失败 3 次会暂停该探针。

流式输出中途断了会切换吗？

不会。首字节之后不再切换供应商，避免已经输出的内容被另一段回答覆盖。上游截断会按瞬态失败从 10 秒起冷却，连续失败逐步退避到 60 秒；客户端自己断开不算供应商故障。

可以多个客户端同时用吗？

可以。TokenHUB 在本机提供一个 HTTP 服务，多个客户端可以同时连接；并发上限取决于上游供应商，TokenHUB 不做额外的排队或限速。

换电脑怎么迁移？

复制 config.json 可以保留供应商、模型与统一模型配置；历史是 history 目录下的 JSONL，也可以复制。secrets.bin 因 Windows 加密绑定，复制后通常无法解密，建议在新机器上重新录入 Key。

支持 macOS 或 Linux 吗？

当前只提供 Windows 安装包（NSIS），开机自启也只在安装版生效。代码基于 Electron，但其他平台尚未打包与验证，不建议直接当作可用版本。

我的提示词会被保存或上传吗？

TokenHUB 不保存提示词和回复正文，也没有遥测。请求内容只会在处理时转发给你选择的供应商；本地历史只记录请求元数据。

Scope

它不做什么

把边界说清楚，比列出更多“特性”更有用。

•
不是负载均衡器。严格按优先级，不轮询、不按延迟或价格自动选路。
•
只覆盖 Chat 与 Messages。不代理 Embeddings、Rerank、Realtime、Batch 等端点。
•
单机单用户。没有团队配额、审计日志或多租户隔离。
•
协议能力依赖扫描。未扫描的组合按预设默认处理，必要时需手动验证。
•
0.1.0 早期版本。配置结构与界面仍可能调整；当前只发布 Windows 安装包。
•
不做内容处理。不缓存、不改写、不审核提示词与回复。
