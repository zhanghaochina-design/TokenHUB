TokenHUB · Practical Guide

把 DeepSeek V4.1 Flash
接进 Claude Code

这是一份从零跑通的实操教程：先装 TokenHUB，再用 Claude Code 桌面版的开发者模式 （或 CLI 的 settings.json）指向本地网关， 配置 OpenCode Go、DeepSeek 与 CommandCode Goat 三家供应商， 最后把 DeepSeek V4.1 Flash 统一成 Claude Code 认识的 claude-sonnet-4-5。 全程一个本地地址，不把 Key 交给第三方中转。

Windows 10 / 11 TokenHUB v0.1.1 Claude Code 桌面版 / CLI 约 15 分钟 无需 Anthropic 订阅

读完后你会得到什么

  • Claude Code 不登录 Anthropic，也能正常读写项目、跑命令；桌面版用开发者模式，CLI 用配置文件。
  • TokenHUB 里同时挂载 OpenCode Go、DeepSeek、CommandCode Goat，按优先级自动选路。
  • Claude Code 只记一个模型名 claude-sonnet-4-5，背后实际跑的是 DeepSeek V4.1 Flash。
  • OpenCode Go 额度耗尽或限流时，请求能自动落到下一家；排错时能在历史里看到真实上游模型。

01 · Overview

先看链路：Claude Code 不需要知道 DeepSeek 叫什么

Claude Code 说的是 Anthropic Messages 协议；OpenCode Go、DeepSeek、CommandCode Goat 的上游形状并不完全一样。 TokenHUB 的工作，就是站在中间把协议、模型名和失败切换都处理掉。

Claude Code Anthropic /v1/messages
→
TokenHUB 127.0.0.1:8787 统一模型 + 协议转译 + 优先级
→
OpenCode Go deepseek-v4.1-flash
DeepSeek deepseek-flash
CommandCode Goat 按其模型列表

示意图只表达关系，不代表固定顺序；实际顺序由「供应商」页从上到下决定。

没有 TokenHUB 时

Claude Code 只能指向一个上游；换供应商要改 Base URL、换模型名、重启客户端，额度用完只能手动切。

有了 TokenHUB 后

所有客户端都指向 127.0.0.1:8787；供应商增删、排序、换 Key 都在本地界面完成。

统一模型解决什么

同一个模型在 OpenCode Go 叫 deepseek-v4.1-flash，在 DeepSeek 官方叫 deepseek-flash；统一后 Claude Code 只认一个名字。

失败时发生什么

额度、限流、5xx 会切到下一家；流式请求一旦开始返回内容就不再切换，避免两段回答互相覆盖。

一句话理解：TokenHUB 是本地网关，不是云端中转。它只监听 127.0.0.1，Key 存在本机，请求只会转发给你配置的供应商。

02 · Checklist

准备清单

缺什么先补什么；只有 TokenHUB 和 Claude Code 是必须安装的软件，三家供应商的 Key 可以边配边补。

Claude Code 桌面版 / CLI 客户端 桌面版用 Developer Mode 配 Gateway；CLI 用 settings.json。二选一即可，也可以都装。注意桌面应用与网页版 claude.ai 不是同一个入口。

CommandCode Goat Key Claude 模型 / 额外兜底 CommandCode 控制台里的 Provider API Key；是否带 DeepSeek 模型以其模型页为准。
Git for Windows 可选 只影响 CLI；桌面版不需要。CLI 在 Windows 上推荐安装，没有时会退回 PowerShell。
Node.js 22+ 仅 CLI 的 npm 安装方式需要 桌面版不需要 Node.js；CLI 用官方安装脚本时也不需要。
  • Windows 10 或 Windows 11；桌面版能正常启动，走 CLI 时能打开 PowerShell / 终端。
  • Claude Code 桌面版已安装，且版本支持 Developer Mode 与第三方推理配置。
  • TokenHUB 安装包已下载，且知道它放在哪个目录。
  • OpenCode Go、DeepSeek、CommandCode Goat 三家的 Key 至少准备好 OpenCode Go 与 DeepSeek。
  • DeepSeek 账户有可用余额；OpenCode Go 订阅在有效期内。

03 · TokenHUB

安装并启动 TokenHUB

先把网关跑起来，再去装客户端。这样 Claude Code 配置完就能直接验证，不用来回切换窗口。

1

下载安装包

打开项目 GitHub Release 页面，下载 TokenHUB-Setup-0.1.1.exe。当前只提供 Windows 安装包，没有 macOS / Linux 版本。

2

安装并启动

双击安装包，按向导选择目录并完成安装。启动后窗口出现即表示主进程已运行；关闭窗口默认最小化到托盘，服务继续监听。

如果 Windows 弹出「已保护你的电脑」，确认文件来自项目 GitHub Release 页面后，点「更多信息」→「仍要运行」。

3

确认服务与端口

打开「概览」，顶部应显示服务运行中。默认监听 127.0.0.1:8787；如果 8787 被占用，应用仍会打开，只是服务未启动，到「设置」换一个端口保存即可。

4

看一眼前面的地址

进入「设置」→「连接信息」，确认 Anthropic Base URL 是 http://127.0.0.1:8787，末尾没有 /v1。OpenAI Base URL 则是 http://127.0.0.1:8787/v1。

本文只用到 Anthropic 入口，因为 Claude Code 走的是 Messages 协议。

5

本地访问 Key：可开可不开

默认关闭，本机程序可以直接访问。开启后，所有 /v1 请求都要带 Bearer 或 x-api-key；桌面版 Gateway 的 API key、CLI 的 ANTHROPIC_AUTH_TOKEN 都要填这个 Key。本文先按关闭处理，配置里用占位值。

6

以后升级：手动检查更新

进入「设置」→「软件更新」，点「检查更新」。TokenHUB 只在你点击时请求 GitHub Release，不会在后台自动检查或下载；发现新版本后点「下载 vX」，完成后再点「重启并安装」。

更新检查只在安装版启用，开发与测试环境不会请求 GitHub。0.1.1 起安装包名为 TokenHUB-Setup-0.1.1.exe（连字符、无空格）。

Key 放在哪里：供应商 Key 与本地访问 Key 都保存在 %APPDATA%\TokenHUB\secrets.bin，由 Windows DPAPI 加密。界面不回显，日志和历史也不落 Key。不要把 secrets.bin 复制到另一台机器或另一个数据目录，通常无法解密。

更新资产要对得上：GitHub Release 里应同时有 latest.yml、TokenHUB-Setup-0.1.1.exe、blockmap 与 SHA256SUMS.txt。缺少 latest.yml 或安装包名不一致时，设置页能查到版本也可能下载失败。

04 · Claude Code

安装 Claude Code 桌面版，打开开发者模式

Claude Code 有两个入口：桌面版（GUI，用 Developer Mode 配 Gateway）和 CLI（用 settings.json）。本文以桌面版为主；终端用户可以直接跳到 7.2。

先分清入口：本文说的是 Claude 桌面版里的 Claude Code（桌面应用，带 Developer Mode 与第三方推理配置），不是网页版 claude.ai。网页版没有本地 Gateway 配置，也无法读取你电脑上的 TokenHUB。

4.1 下载并安装 Claude Code 桌面版

1

从官方页面下载

打开 claude.com/product/claude-code，选择 Windows 安装包。官方桌面版文档在 code.claude.com/docs/zh-CN/desktop-quickstart。

国内网络访问官网不稳定时，优先找官方提供的其他下载入口或可信的离线安装包；不要运行来路不明的第三方安装包，来源无法核对时宁可改用 CLI 路线。

2

安装并启动

双击安装，完成后启动 Claude Code 桌面版。桌面版不需要 Node.js、Git for Windows 或 npm；这些只在 CLI 路线用到。

如果启动后停在登录界面，先不要登录——下一步用开发者模式接管认证。

3

开启 Developer Mode

在顶部菜单依次点 Help → Troubleshooting → Enable Developer Mode…，在确认框里点 Enable。应用会自动重启。

重启后顶部菜单多出 Developer 项，说明开发者模式已开启。不同版本菜单文字可能略有差异，认准 Developer Mode / 开发者模式。

找不到 Developer 菜单：先把 Claude Code 桌面版升级到最新版本，再重新执行 Help → Troubleshooting → Enable Developer Mode，并完全退出、重新打开应用。旧版本没有第三方推理配置，无法接入 TokenHUB。

4.2 可选：安装 Claude Code CLI

如果你习惯终端、IDE 集成或脚本自动化，或者桌面版不接受 HTTP 本地网关，可以改用 CLI。CLI 与桌面版是两条独立路径，配置互不影响；只用桌面版可以跳过这一节。

路线 A：官方安装脚本

在 PowerShell 里执行（普通用户即可，不需要管理员权限）：

PowerShell
irm https://claude.ai/install.ps1 | iex

装完重新打开终端，验证：

PowerShell
claude --version
claude doctor

路线 B：npm 镜像（国内网络更稳）

先装 Node.js 22 或更高版本。已经装过 Node 的，先确认版本：

PowerShell
node --version
npm --version

没有 Node.js 的，可以用 winget 装 LTS，或者去 npmmirror 的 Node 镜像下载安装包。然后把 npm 源切到国内镜像：

PowerShell
npm config set registry https://registry.npmmirror.com
npm install -g @anthropic-ai/claude-code

npm 安装的也是 Claude Code 的原生程序，只是通过 npm 分发。如果遇到 claude native binary not installed，先清缓存再重装：

PowerShell
npm cache clean --force
npm install -g @anthropic-ai/claude-code

验证 CLI 安装：运行 claude --version 能输出版本号；claude doctor 能正常检查环境。若提示「claude 不是内部或外部命令」，多半是 npm 全局目录不在 PATH，重开终端或检查 npm 的全局前缀。

首次启动 CLI 时如果提示登录 Anthropic，先按 Ctrl+C 退出；7.2 会用 settings.json 接管认证。

05 · Providers

在 TokenHUB 里配置三个供应商

「供应商」页从上到下就是路由顺序。三家都加上，先不纠结谁第一；等模型和 Key 都验证通过，再拖动排序。 每个供应商都走同一套流程：添加 → 选预设 → 填 Key → 测试连接 → 保存。

建议顺序供应商预设 Base URL额度适配器本文角色
1 OpenCode Go https://opencode.ai/zen/go/v1 OpenCode Go 额度接口 主力，优先消耗订阅额度
2 DeepSeek https://api.deepseek.com/v1 DeepSeek 余额接口 同模型直连兜底
3 CommandCode Goat https://api.commandcode.ai/provider/v1 CommandCode 套餐接口 Claude 模型 / 额外兜底

顺序只是本文示例。你可以按自己的套餐、价格和延迟调整；唯一要记住的是：上面的先用，失败或冷却才轮到下面。窄屏下表格可左右滑动查看完整列。

编辑供应商时还有一个可选的「Anthropic Base URL」：它只用于 Claude 格式的 /messages 请求，需要填含版本路径的地址。OpenCode Go 与 CommandCode Goat 留空即可（默认与 Base URL 相同）；DeepSeek 官方域名留空时会自动使用 https://api.deepseek.com/anthropic/v1。只有自建或中转服务才需要手动覆盖。

5.1 OpenCode Go：主力供应商

OpenCode Go 是 OpenCode 的付费订阅，用它自己的 Go API Key。它和 Zen 共用一套凭据基础设施，但 Zen 的 Key 不会自动带 Go 权益；如果测试连接只看到 Zen 模型或额度不对，先确认自己开通的是 Go。

1

添加供应商

进入「供应商」→「添加供应商」，预设选择 OpenCode Go。名称、Base URL、额度适配器会自动填好，不需要手改。

2

填 API Key

把 OpenCode Go 控制台创建的 Key 粘进去。Key 只保存到本机，界面上不会回显；编辑时留空表示沿用旧 Key。

3

测试连接

点「测试连接」。成功时会显示发现的模型数量与额度摘要；重点确认模型列表里有 deepseek-v4.1-flash。额度接口偶尔失败不影响模型发现，可以先保存，稍后看概览卡。

4

保存并置顶

保存后回到供应商列表，拖动行首手柄，把 OpenCode Go 放到第一位。它是本文的主力通道。

不要填错模型：OpenCode Go 预设对应的是 Go 订阅的 deepseek-v4.1-flash（付费版，1M 上下文）。deepseek-v4.1-flash-free 是 Zen 渠道的免费版（约 200K 上下文），不要把它填进这个 Go 预设；端点和权益都不是一回事。

OpenCode Go 的额度卡会显示 5 小时 / 周 / 月三个窗口；具体上限由套餐和模型决定。额度探针默认每 5 分钟（300 秒）探测一次，可在设置页调整为 10–3600 秒；额度耗尽会自动进入冷却并切到下一家。

5.2 DeepSeek：同模型直连兜底

DeepSeek 官方同时提供 OpenAI 兼容的 /v1 和 Anthropic 兼容的 /anthropic/v1。它的作用是：当 OpenCode Go 额度用完、限流或临时不可用时，Claude Code 仍然能用到同一个 DeepSeek V4.1 Flash，只是换成按量计费。

1

添加预设

「添加供应商」→ 预设选 DeepSeek。Base URL 自动填 https://api.deepseek.com/v1；下面的「Anthropic Base URL」留空即可，官方域名会自动使用 https://api.deepseek.com/anthropic/v1。额度适配器为「DeepSeek 余额接口」。

2

填 Key 与余额阈值

把 platform.deepseek.com 创建的 API Key 粘进去。低余额阈值默认 0.5 美元，余额低于这个值会被视为耗尽；按自己的用量改。

3

确认模型 ID

当前 DeepSeek V4.1 Flash 的官方 API 模型 ID 是 deepseek-flash。旧的 deepseek-chat 与 deepseek-reasoner 已在 2026 年 7 月 24 日退役，不要照着旧教程填。

4

保存并观察余额

保存后概览会出现余额卡。余额随额度探针刷新，默认每 5 分钟一次；探测失败会按 30 秒到 15 分钟退避重试，不会永久停用。余额刷新慢是正常现象。

DeepSeek 官方有独立的 Anthropic 入口：Claude Code 发来 Messages 请求时，TokenHUB 会直连 https://api.deepseek.com/anthropic/v1/messages，不需要先转成 Chat。只有供应商被扫描或标记为不支持 Messages 时，才会退回 Chat 形状并做双向转译。

5.3 CommandCode Goat：Claude 模型与额外兜底

CommandCode Goat 的定位和上面两家不同：它既有 Claude 系模型，也可能带 DeepSeek 系模型。把它加进来，主要是为了在 OpenCode Go 与 DeepSeek 都不可用时还有一条路，同时让 Claude Code 的 Claude 模型槽位有真正的 Claude 可用。

1

添加预设

「添加供应商」→ 预设选 CommandCode Goat。Base URL 自动填 https://api.commandcode.ai/provider/v1，额度适配器为「CommandCode 套餐接口」。

2

填 Provider API Key

用 CommandCode 控制台创建的 Provider API Key，不是普通登录密码。填完先点「测试连接」，能看到模型列表再保存。

3

看模型列表，不要硬填

CommandCode 的模型 ID 可能是 claude-sonnet-4-5 这种 Claude 名，也可能是 deepseek/... 这种带命名空间的写法。是否有 DeepSeek V4.1 Flash、ID 具体叫什么，以「模型」页显示为准；没有就不要为了凑统一模型硬填。

4

保存，放到第三位

本文把它放在 OpenCode Go 与 DeepSeek 之后。它不是主力，但在 Claude 模型槽位或前两家冷却时很有用。

额度探针的 401 / 403 不是一回事：CommandCode 用的是控制台同款内部接口。401 才表示 Key 无效；403 或响应无法识别按「探针失败」处理，不要因为额度卡报错就立刻换 Key。未识别的套餐按月上限 70 美元估算，余额高于上限时以余额定标。

5.4 调优先级，做一次兼容性扫描

供应商列表的顺序就是路由顺序。本文建议：OpenCode Go → DeepSeek → CommandCode Goat。拖动行首手柄即可保存新顺序；开关可以临时停用某一家，不用删除。

1

刷新模型目录

保存供应商后，到「模型」页点「刷新全部模型」。模型页会合并所有已启用供应商的目录；同名模型只出现一次。

2

扫描调用方式

在「调用方式兼容性」里，对每个供应商点「扫描」。TokenHUB 会对每个模型向 Anthropic 入口的 /messages 与 Base URL 的 /chat/completions 各发一个 max_tokens=16 的请求，把结果写进 protocolSupport。DeepSeek 官方会自动使用 /anthropic/v1/messages。

3

看 A / O 徽标

A 表示 Anthropic Messages 可用，O 表示 OpenAI Chat 可用。绿色对勾表示扫描确认可用，红色表示明确不支持。扫描不写历史、不计供应商冷却；只有同一模型两个入口都 401 才提前停止。

供应商协议特点对本文的影响
OpenCode Go 两个入口都可用，优先保持客户端原本的形状 Claude Code 的 Messages 请求可以直接走上游 /messages，少一次转译。
DeepSeek 官方 Anthropic 入口是 /anthropic/v1，与 OpenAI 的 /v1 不同；TokenHUB 对官方域名自动推导，也可用 Anthropic Base URL 覆盖 Claude Code 的 Messages 请求可以直连；自建 / 中转服务要确认 Anthropic 入口，否则可能 404 / 405。
CommandCode Goat claude* 只走 /messages，其余只走 /chat/completions 预设会按模型名自动判断；扫描可以确认每个模型的实际能力。

到这里先停一下：确认三家供应商都已启用、模型页能看到 deepseek-v4.1-flash 与 deepseek-flash，再去做统一模型。否则后面 Claude Code 报 404，很难判断是别名问题还是供应商没拉到模型。

06 · Unified model

把 DeepSeek V4.1 Flash 统一成 claude-sonnet-4-5

Claude Code 默认会按 Claude 的模型名发请求。我们不需要改 Claude Code 的源码，只要在 TokenHUB 里创建一个统一模型： 本地 ID 用 Claude 认识的名字，目标写上各家真实的上游模型 ID。

统一模型解决的是「同一个模型、不同上游名字」的问题。OpenCode Go 叫 deepseek-v4.1-flash，DeepSeek 官方叫 deepseek-flash，CommandCode 可能又是另一种写法。统一之后，Claude Code 只发 claude-sonnet-4-5，TokenHUB 按供应商优先级挑一个目标转发。

1

打开统一模型

进入「模型」页，找到「统一模型」卡片，点「添加统一模型」。

2

填统一模型 ID

在「统一模型 ID」里填 claude-sonnet-4-5。这是 Claude Code 能识别的 Sonnet 模型名；后面再用 ANTHROPIC_MODEL 把它锁死，就不会发带日期后缀的版本名。

3

逐个添加上游目标

每个供应商一行：左边选供应商，右边填该供应商模型列表里的真实 ID。不确定就从输入框的下拉候选里选，不要凭记忆手打。

4

保存并检查模型目录

保存后，被映射的原始 ID 会从 /v1/models 隐藏，模型目录只显示 claude-sonnet-4-5。原始 ID 仍然可以用 providerId/原始ID 强制访问。

供应商目标上游模型 ID说明
OpenCode Go deepseek-v4.1-flash 主力目标。Go 套餐内的付费版，1M 上下文；以模型页实际显示为准。
DeepSeek deepseek-flash 同模型直连兜底。旧 deepseek-chat 已退役，不要填旧 ID。
CommandCode Goat deepseek/… 仅当模型页里确实有 DeepSeek V4.1 Flash 时添加；没有就留空，不影响别名保存。

同名自动纳入：如果某个供应商原生就有 claude-sonnet-4-5（例如 CommandCode Goat），它会被自动纳入这个统一模型的候选。显式映射优先，其余同名供应商自动加入。这意味着前两家都不可用时，可能由真正的 Claude 兜底——这不是 bug。如果你要求「任何时候都只能用 DeepSeek」，请改用下面的中性 ID，或停用 CommandCode。

备选：用中性 ID deepseek4.1flash

如果你不希望和 Claude 原生模型同名，也可以把统一模型 ID 取成 deepseek4.1flash。这样不会自动吸收任何同名的 Claude 模型，路由范围完全由你列的 targets 决定。代价是 Claude Code 那边必须显式设置 ANTHROPIC_MODEL=deepseek4.1flash，并且把 Haiku / Sonnet / Opus 等模型槽位都指向它；否则 Claude Code 仍会发 claude-... 的名字。

推荐：claude-sonnet-4-5

Claude Code 内置槽位直接命中；配置最少。注意同名的真实 Claude 供应商可能自动加入候选。

可控：deepseek4.1flash

不会和 Claude 模型撞名；但所有模型槽位都要手动指向它，漏一个就可能 404。

07 · Connect Claude Code

让 Claude Code 指向 TokenHUB

桌面版和 CLI 是两条独立路径，二选一即可：桌面版用 Developer Mode 里的第三方推理配置， CLI 用 settings.json。两边的模型名都填统一模型 claude-sonnet-4-5。

7.1 Claude Code 桌面版：Developer Mode + Gateway（推荐）

这是你前面打开的开发者模式的真正用途：把桌面版的推理请求接到 TokenHUB。配置一次，桌面版的 Chat、Cowork、Code 都会走同一个网关。

1

打开第三方推理配置

在顶部菜单点 Developer → Configure Third-Party Inference…。如果这个菜单项不存在，回到第 4.1 节确认 Developer Mode 已开启并重启过应用。

2

连接方式选 Gateway

在 Connection 区块选择 Gateway（Anthropic-compatible）。如果界面有 Credential kind / 凭据类型，选择 Static API key；没有这一项就跳过。

3

填写 TokenHUB 的地址与 Key

字段填写内容说明
Gateway base URLhttp://127.0.0.1:8787TokenHUB 的 Anthropic 根地址，不要加 /v1。
Gateway API keysk-local-placeholderTokenHUB 关闭本地访问 Key 时填任意非空值；启用了就填那个 Key。
Gateway auth schemeBearerTokenHUB 接受 Bearer 与 x-api-key；按界面默认即可。
Gateway extra headers留空TokenHUB 不需要额外请求头；除非你前面加了自定义反向代理。

窄屏下表格可左右滑动查看完整字段。

4

添加统一模型

在 Model list / 模型列表里点刷新，选择或手动添加 claude-sonnet-4-5。模型列表来自 TokenHUB 的 /v1/models；如果桌面版没有自动拉到，就手动填这一个统一 ID，不要填上游的 deepseek-v4.1-flash。

5

应用到本机并重启

点 Apply locally（不要选云端同步），再点 Relaunch now。桌面版重启后，新建一个会话，模型选择 claude-sonnet-4-5，发一句「只回复 OK」验证。

两个版本差异：有的桌面版会在开发者设置里提供 Allow External URLs / 允许外部地址的开关，接本地网关时一并打开；有的版本强制 Gateway URL 使用 HTTPS。如果 HTTP 回环地址被拒绝，改用 7.2 的 CLI，或在 TokenHUB 前面加一层本地 HTTPS 反向代理，不要把 TokenHUB 直接暴露到公网。

为什么这里不填上游模型：桌面版只认你给它的模型 ID。统一模型 claude-sonnet-4-5 会在 TokenHUB 内部映射到 OpenCode Go 的 deepseek-v4.1-flash 和 DeepSeek 的 deepseek-flash。桌面版填上游 ID 反而会绕过别名，失去自动切换。

7.2 Claude Code CLI：settings.json（可选）

如果你只用桌面版，可以跳过这一节。CLI 和桌面版可以同时配置，它们各自保存认证信息，互不冲突。

1. 打开配置文件

Windows 用户级配置文件路径是：

路径
%USERPROFILE%\.claude\settings.json

没有 .claude 目录就新建一个；没有 settings.json 就新建文件。项目级配置在项目根目录的 .claude\settings.json，适合按项目覆盖；本文用用户级，一次配好所有项目。

2. 写入完整配置

把下面这段写进去。前三个是核心；后面几个是模型槽位，用来防止 Claude Code 用 Haiku / Opus / 子 Agent 的名字发请求时找不到统一模型。

JSON · %USERPROFILE%\.claude\settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8787",
    "ANTHROPIC_AUTH_TOKEN": "sk-local-placeholder",
    "ANTHROPIC_MODEL": "claude-sonnet-4-5",
    "ANTHROPIC_SMALL_FAST_MODEL": "claude-sonnet-4-5",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-sonnet-4-5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-4-5",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-sonnet-4-5",
    "CLAUDE_CODE_SUBAGENT_MODEL": "claude-sonnet-4-5"
  }
}
  • ANTHROPIC_BASE_URL 填 TokenHUB 的 Anthropic 根地址，不要加 /v1；Claude Code 会自己拼 /v1/messages。
  • ANTHROPIC_AUTH_TOKEN 在 TokenHUB 关闭本地访问 Key 时可以填任意非空占位值；如果启用了本地 Key，必须换成那个 Key。
  • ANTHROPIC_MODEL 必须是「模型」页里存在的 ID；本文是统一模型 claude-sonnet-4-5。
  • 后面几个模型槽位不是必需，但强烈建议一起写；Claude Code 的后台任务、子 Agent 可能用不同槽位，漏掉就会出现「主对话正常、子任务 404」。

如果你的 Claude Code 版本只读 ANTHROPIC_API_KEY：把同一个 Token 也写成 ANTHROPIC_API_KEY。不要同时保留官方登录态和自定义 Token；两套认证混在一起时，先清掉旧的 shell 环境变量，再重开终端。

3. 重开终端并验证

保存文件后关闭当前终端，重新打开。进入项目目录运行 claude，然后用两个命令确认配置真的生效：

Claude Code 会话内
/status
/model

/status 里应能看到 Anthropic Base URL 指向 http://127.0.0.1:8787；/model 应显示 claude-sonnet-4-5。也可以用非交互模式做一条最小验证：

PowerShell
claude -p "只回复：链路正常"

如果它仍然要求登录 Anthropic：先检查配置文件路径是不是 %USERPROFILE%\.claude\settings.json、JSON 有没有语法错误、项目里是否有另一份 .claude\settings.json 覆盖了它。再看 shell 里有没有旧的 ANTHROPIC_BASE_URL 或 ANTHROPIC_API_KEY。配置正确时，Claude Code 会直接用 TokenHUB，不会走官方登录。

不想改文件：用 PowerShell 设置用户环境变量

可以改用 setx 写入用户环境变量，然后重开终端：

PowerShell
setx ANTHROPIC_BASE_URL "http://127.0.0.1:8787"
setx ANTHROPIC_AUTH_TOKEN "sk-local-placeholder"
setx ANTHROPIC_MODEL "claude-sonnet-4-5"

这种方式只设置三个核心变量，模型槽位仍需自己补。settings.json 更好维护，也更适合多项目；两种方式不要同时写不同的值。

08 · Verify

验证：确认请求真的走了 DeepSeek

Claude Code 能回答不代表走对了上游。打开 TokenHUB 的概览和历史，看供应商与上游模型字段，才是可靠证据。

1

发一条请求

在 Claude Code 里让它读一个文件或直接问一句「只回复 OK」。请求会经过 TokenHUB，概览页的今日请求数应增加。

2

看最近请求

打开 TokenHUB「概览」→「最近请求」，展开刚才那条。重点看三列：供应商、上游模型、协议。正常情况应是 OpenCode Go + deepseek-v4.1-flash。

3

测试一次切换

到「供应商」页把 OpenCode Go 的开关关掉，再发一条请求。历史里应显示 DeepSeek + deepseek-flash，说明兜底链路生效。测试完记得把开关打开。

如何确认不是 Claude 在回答：不要问模型「你是谁」，模型自报身份不可靠。展开历史记录，看「上游模型」是 deepseek-v4.1-flash 还是 deepseek-flash；如果显示 claude-sonnet-4-5，说明这次被 CommandCode 的原生 Claude 模型接走了。再看「切换来源」，能知道是否发生过供应商切换。

失败时会发生什么

情况TokenHUB 的行为你要做什么
OpenCode Go 额度耗尽 / 429 被判为额度问题 切到下一个可用供应商，供应商进入额度冷却（默认 5 小时，可配置） 等冷却，或到概览卡点「恢复」；也可以临时停用该供应商。
429 限流 切到下一个可用供应商；冷却按 Retry-After，缺失时 60 秒 通常无需操作，等冷却结束。
401 / 403 鉴权失败 跳过该供应商，继续尝试其他候选 更新对应供应商的 Key；更新后状态会自动清除，或手动点恢复。
5xx / 网络错误 / 超时 先按需换协议入口，再切到下一个供应商；瞬态冷却 10 秒起，连续失败退避到 60 秒 看历史里的错误分类；频繁出现时检查网络或上游状态。
404 模型不存在 先试另一协议入口，再切下一个有该模型的供应商，并触发一次目录刷新（60 秒限流） 核对统一模型的 targets 是否与模型页 ID 完全一致。
400 / 422 请求本身有误 不切换供应商；首字节前可能先换协议入口重试一次 看错误体，通常是参数或上下文问题，不是 Key。
流式已出首字节后中断 结束当前流，不切换供应商；按瞬态冷却，客户端主动断开除外 避免把半截回答重放到另一家；可以重新发起请求。
全部候选都不可用 返回 503；有冷却中的候选时附带 Retry-After（最短剩余秒数） 按剩余秒数等待，或检查供应商是否都被禁用 / Key 失效。

流式请求只有首字节前允许切换。一旦开始返回内容，TokenHUB 不会把请求重放到另一家，避免客户端收到两段互相矛盾的回复。所以「回答到一半断了」不会自动续写；重新发起请求即可。

09 · Troubleshooting

常见问题：按症状定位

先看 Claude Code 报什么，再看 TokenHUB 历史里的错误分类；不要一上来就换 Key。

Claude Code 仍然弹出 Anthropic 登录 / 桌面版没有走 Gateway

桌面版：确认 Developer Mode 已开启，Developer → Configure Third-Party Inference 里已选 Gateway、填了本地地址和 Key，并且点过 Apply locally → Relaunch now。Gateway base URL 填 http://127.0.0.1:8787，不要加 /v1；如果版本要求 HTTPS 或打开了 Allow External URLs，按第 7.1 节的提示处理。

CLI：检查配置文件是否在 %USERPROFILE%\.claude\settings.json；JSON 是否合法（不能有尾逗号）；项目里是否有 .claude\settings.json 覆盖；shell 里是否还有旧的 ANTHROPIC_BASE_URL / ANTHROPIC_API_KEY。改完后重开终端，运行 /status 确认地址。

401：Unauthorized

两种可能：客户端带的本地 Token 与 TokenHUB 的本地访问 Key 不一致；或者某个供应商的 Key 失效。桌面版检查 Gateway API key，CLI 检查 ANTHROPIC_AUTH_TOKEN，两者都要和设置页的本地访问 Key 一致（未启用本地 Key 时填任意非空值）。再看 TokenHUB 概览卡上该供应商是否显示「鉴权失败」；供应商 Key 更新后会自动恢复。

404：model_not_found

最常见的原因是统一模型的 target 与模型页显示的上游 ID 不完全一致，包括命名空间前缀、大小写和短横线。到「模型」页确认供应商确实有该模型，再编辑统一模型，从下拉候选里选，不要手打。若模型是刚加的，先点「刷新全部模型」。

桌面版还要确认 Model list 里选的是统一 ID claude-sonnet-4-5，不是上游 ID；CLI 则检查 ANTHROPIC_MODEL 与所有模型槽位。

DeepSeek 的 Messages 入口 404 / 405

DeepSeek 官方 Anthropic 入口在 /anthropic/v1，不是 OpenAI 的 /v1。用官方域名时 TokenHUB 会自动推导；如果你用的是自建或中转的 DeepSeek 兼容服务，编辑供应商，在「Anthropic Base URL」里填它真正的 Claude 格式地址（含版本路径）。留空时该地址会回退到 Base URL，可能因此打到错误的路径。

400：OpenCode Go 提示缺少 session 或 User-Agent

OpenCode Go 要求 x-opencode-session 与可识别的 User-Agent。走 TokenHUB 时它会自动补；只有你用 curl 直连上游才需要自己带。出现这个错误时，先确认请求确实发给了 TokenHUB，而不是旧配置里的上游地址。

503：所有候选都不可用

三家供应商可能都在冷却、被禁用或鉴权失败。看响应头 Retry-After，按剩余秒数等待；也可以到概览卡点「恢复」手动清零，或到供应商页检查开关和 Key。刚测试完切换时，记得把停用的供应商重新打开。

CommandCode 额度卡报错，但模型能用

CommandCode 的额度接口是控制台同款内部接口。403 或响应无法识别会按探针失败处理，不代表 Key 无效；401 才是 Key 无效。模型能用就先继续用，额度卡的问题可以稍后看；未识别套餐按月上限 70 美元估算。

主对话正常，子任务或后台任务 404

CLI：Claude Code 可能用 Haiku / Opus / 子 Agent 槽位发请求，而你只映射了 claude-sonnet-4-5。把 ANTHROPIC_DEFAULT_HAIKU_MODEL、ANTHROPIC_DEFAULT_SONNET_MODEL、ANTHROPIC_DEFAULT_OPUS_MODEL、CLAUDE_CODE_SUBAGENT_MODEL 都设成同一个统一模型 ID。

桌面版：先在模型下拉里固定选 claude-sonnet-4-5；如果 Chat / Cowork / Code 仍会自动切到 Haiku 或 Opus，给这些 Claude 模型名也建同样目标的统一模型，或在设置里关闭自动切换（以当前版本为准）。

模型列表是空的 / 没有 DeepSeek

先点「刷新全部模型」。有些服务不提供 /models，这时编辑供应商，在「手动模型」里填模型 ID，多个用逗号分隔。请求一个本地目录里没有的模型也会触发一次目录刷新，但 60 秒内最多一次。

桌面版的 Model list 如果为空，直接手动添加 claude-sonnet-4-5；它只要能从 TokenHUB 的 /v1/models 查到就会生效。

DeepSeek 余额卡很久不更新

额度探针默认每 5 分钟刷新一次，可在设置页调整为 10–3600 秒。探测失败不会改变路由状态，会按 30s / 1m / 2m / 4m / 8m / 15m 退避重试；任何一次成功（含手动刷新）都会清零失败计数，不会永久停用探针。余额低于阈值时会被视为耗尽。

端口 8787 被占用 / 改了端口

应用仍然会打开，只是服务未启动。到「设置」换一个可用端口并保存，再同步改客户端：CLI 改 ANTHROPIC_BASE_URL，桌面版改 Gateway base URL，然后重启客户端。配置、Key 和历史不受影响；新端口启动失败时旧端口会继续服务。

设置页的「检查更新」不可用 / 下载失败

只有安装版启用更新检查，开发与测试环境不会请求 GitHub；更新只能手动触发，不会后台自动检查。如果已经发现新版本但下载失败，确认 GitHub Release 里同时有 latest.yml、TokenHUB-Setup-<版本>.exe 与 blockmap；缺少 latest.yml 或安装包名不一致时，更新器会找不到资产。

Claude Code 桌面版找不到 Developer 菜单 / Gateway URL 被拒绝

找不到 Developer 菜单：升级 Claude 桌面版到支持第三方推理的版本，按 Help → Troubleshooting → Enable Developer Mode 开启，并完全退出、重新打开应用。不要把网页版 claude.ai 当成桌面客户端；网页版没有 Developer Mode 与 Gateway 配置。

Gateway URL 被拒绝：先确认填的是 http://127.0.0.1:8787，没有多余路径；如果版本强制 HTTPS，改用 7.2 的 CLI，或在 TokenHUB 前加本地 HTTPS 反向代理。不要为了绕过校验把 TokenHUB 暴露到公网。

10 · Boundaries

安全边界：它保护什么，不做什么

TokenHUB 是本地进程，不是云端中转。把边界说清楚，比多列几个特性更有用。

只监听回环地址

服务绑定 127.0.0.1，不接受局域网或公网连接，不需要开放防火墙端口。

Key 由 DPAPI 加密

供应商 Key 与本地访问 Key 存在 secrets.bin，界面不回显，日志与历史不落 Key。

历史只存元数据

记录模型、供应商、Token、耗时、首字节、错误分类与切换来源，不保存提示词和回复正文。

没有遥测上报

不做用量分析或行为上报；只有你主动发起的请求会到达对应供应商。

可选的本地访问保护

开启后请求必须带 Bearer 或 x-api-key；关闭时本机程序可直接访问，适合单人开发机。

迁移注意

config.json 与历史可以复制；secrets.bin 与写入它的 Windows 用户 / 实例绑定，复制到其他数据目录通常会解密失败。换机建议重新录入 Key。

它不做什么

  • 不是负载均衡器：严格按优先级，不轮询、不按延迟或价格自动选路。
  • 只覆盖 Chat 与 Messages：不代理 Embeddings、Rerank、Realtime、Batch 等端点。
  • 单机单用户：没有团队配额、审计日志或多租户隔离。
  • 当前只发布 Windows 安装包；macOS / Linux 尚未打包验证。
  • 0.1.1 版本：配置结构与界面仍可能调整。

不要把本地服务暴露到公网。TokenHUB 的设计前提是「只在本机用」。如果确实需要给局域网其他设备用，请自己加反向代理、鉴权和 TLS，并确认上游供应商条款允许；这不是本文的默认配置。

  • OpenCode Go 已启用并放在第一位，测试连接能看到 deepseek-v4.1-flash。
  • DeepSeek 已启用，余额卡有数据，模型页能看到 deepseek-flash。
  • CommandCode Goat 已启用；模型列表里有 Claude / DeepSeek 模型时再按需映射。
  • 统一模型 claude-sonnet-4-5 至少映射了 OpenCode Go 与 DeepSeek 两个目标。
  • 桌面版已 Apply locally 并重启，模型下拉里能选到 claude-sonnet-4-5，新建会话能返回内容。
  • 如果使用 CLI：/status 指向 127.0.0.1:8787，/model 显示统一模型 ID，claude -p "只回复：链路正常" 能返回内容。
  • TokenHUB 历史里，上游模型是 deepseek-v4.1-flash；停用 OpenCode Go 后能切到 deepseek-flash。

CLI 最小配置片段

JSON · 最小可用
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8787",
    "ANTHROPIC_AUTH_TOKEN": "sk-local-placeholder",
    "ANTHROPIC_MODEL": "claude-sonnet-4-5"
  }
}

如果只用主对话，这三行就够；一旦出现子任务 404，再补上 7.2 节的 Haiku / Sonnet / Opus / 子 Agent 槽位变量。

CLI 常用命令

桌面版按 7.1 的 GUI 配置，不需要这些命令；下面只适用于 CLI。

场景命令
检查 Claude Code 版本claude --version
检查安装环境claude doctor
查看当前 API 配置/status
查看 / 切换模型/model
非交互验证claude -p "只回复：链路正常"
npm 镜像安装npm install -g @anthropic-ai/claude-code

最后一句话：Claude Code 只是前端，TokenHUB 才是路由层。把统一模型 ID 设成 Claude 认识的名字，把上游 ID 留给 TokenHUB 去匹配；以后换供应商、换套餐、换 Key，都不需要再动 Claude Code 的配置。
